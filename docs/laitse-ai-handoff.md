這是一個具有辦公室／共享空間感的虛擬場域，裡面有不同房間，虛擬人物能移動並聚在同一個會議室。主講人在房內開啟廣播與分享畫面，參加的人用按讚、「我想聽」「這個實用」、文字彈幕或圖案回應。

## 2. 故事起點與保留下來的需求

最初是科內分享：主講人投影，多數聽眾在同一個實體會議室，也可能有人遠端觀看。聽眾希望按「講得好」「我想學」、打字或送彈幕，講者能即時感受反應。

後來使用者提出 Gather Town 的參考，將方向擴展為有角色、能共同活動的空間。曾談過虛擬辦公，之後明確要求不限制應用情境。最新描述又確認辦公室／共享空間的感覺，但這不表示只能給企業使用。

必須保留：

- 現場與遠端能在同一個虛擬房間參與。
- 現場手機能只送互動，不必重看直播或開聲音。
- 聽眾有不打斷講者的回應方式。
- 產品有趣且有共同在場感。
- 共享空間可以承接工作、分享、課程、社群及朋友聚會。

## 3. 從 Roamingle 到來坐的命名故事

早期討論過 Wavvy、Nooko、Deskmoss、Deskglade 等名字。Nooko 被使用者指出重名很多；Deskmoss 搜尋到同名軟體；其他名字有的過於限制辦公或植物情境。

使用者曾選擇 Roamingle（Roam＋Mingle），並產出第一版文件。之後轉向台語諧音命名，要求像台語聲音轉成中文字的品牌，而不是硬湊字義。

反覆比較後，使用者指定以 **「來坐」** 發想中英文。助手提出 **LaiTse**，並整理為「來坐 LaiTse」；使用者在這個方向上補充產品定位，接著同意更新文件。

「來坐」是一句自然的邀請：有事可以討論，沒事也能進來待著。中文保留原字；英文 LaiTse 來自台語聲音 lâi tsē 的品牌拼寫，不宣稱是英文單字。

- 品牌：來坐 LaiTse。
- Repo slug 建議：`laitse`；本機 Git 專案已存在，遠端狀態未查核。
- 邀請文案建議：有空，來坐。
- 標語建議：有你的位置，也有一起的空間。
- 標語、美術及英文標語仍可調整；「遊聚」與其他舊中文名皆未採用。
- 中文／英文同名、網域、商標及帳號尚未查核，不宣稱可註冊。

## 4. 最新需求的權威摘要

使用者最新描述：

> 是個虛擬空間，有辦公室或共享空間的感覺，有不同空間。虛擬人物聚在同一個會議室，可以開廣播跟分享畫面；參加的人可以按讚、「我想聽」「這個實用」，送互動彈幕或圖案。

「我向聽」依語意整理成「我想聽」。不要將舊預設按鈕「求展開」等當成新版本的主需求。

這次更新的 PRD 已將下列能力列 P0：

1. 預設共享場景、開放空間與有門的會議室；未鎖可直接入房、上鎖需密碼。
2. 虛擬人物、基本移動與真實多人同步。
3. 開放空間依人物距離接收廣播，會議室內全房收聽；站內螢幕分享沿用房內授權。
4. 房內文字、圖案、彈幕與三種預設回饋。
5. 現場只互動模式、遠端觀看模式、房間深連結與 QR Code。
6. 主持權限、展示端、跨房隔離與重連處理。

## 5. 已確認方向與設計提案的界線

已確認：品牌方向、共享空間、多房間、虛擬人物同房活動、廣播／畫面分享及互動類型；2026-11-02 補入自研、排除 WorkAdventure 與像素人物。

PRD 裡的具體預設仍是可討論提案：

- 首版每房一位主講人、一個分享來源。
- 一個角色同時屬於一個房間、離房停止發布。
- 管理者／主持人／主講人分權與暱稱訪客流程。
- 房間長期存在、Session 表示單次活動的模型。
- 50 人試驗規模、1 秒互動延遲目標、限流與字數上限。
- 分享視窗搭配瀏覽器展示頁的現場投影方法。
- 首版不要求攝影機、錄影、自訂圖片上傳或完整地圖編輯器；開放空間距離廣播已依DEC-011納入核心。

目前人物像素圖與可獨立部署的服務界線已指定；框架、資料庫、影音服務、其他美術、部署平台、預算與工期未指定。不要把研究建議當成使用者技術決策。

## 6. 後續收到實作指令的交辦順序

先執行 POC-00～07 的證據門檻；以下為通過後的 MVP 接續參考，不能跳過 POC 或把 POC 原型直接改稱 MVP。

1. 閱讀最新對話與配套 PRD，檢查目標 repo 和 AGENTS.md，沿用存在的專案慣例。
2. 展示可檢視的空間與房間流程，提出角色操作、美術及影音方案的具體取捨。
3. 技術驗證站內麥克風廣播、螢幕分享、同房訂閱及跨房隔離。確認服務成本、瀏覽器支援與權限行為。
4. 做出「角色進大廳 → 走入會議室 → 主講人廣播／分享 → 觀眾互動 → 切房」的真實多人切片。
5. 加上掃碼直接入房與只互動模式，讓實體會議室聽眾不必先走圖，也不造成音訊回授。
6. 完成主持管理、活動結束、權限撤銷、斷線重連與事件去重。
7. 依 PRD 做兩房、多裝置與手機驗收，再進行真實分享試用。
8. 若開始對外採用品牌，再分開查核同名、網域、帳號與商標；購買或付費資源依使用者授權執行。

## 7. 交付判定與常見陷阱

- 不能只做播放器＋聊天頁就稱完成共享空間。
- 不能將虛擬人物與多房間延到 MVP 之後。
- 單頁模擬的人物、彈幕與按讚不等於多人同步。
- 外部直播嵌入不能替代站內廣播與畫面分享。
- 房間隔離要涵蓋媒體與互動授權，不只是前端隱藏。
- 活動結束停止媒體，不應直接刪除房間與全部角色。
- 移動是核心體驗，但掃碼進會議室的聽眾應有直接入房選項。
- 不強迫參與者開麥、開鏡頭或播放有聲內容。
- 不把一般聊天自動投成彈幕。
- 人物像素圖已由後續人類指示確認；不要擴張成所有場景與 UI 都必須像素風，也不等於企業監控／出勤工具。
- 實作回報須分清已完成、模擬、未測試及尚待決策。
