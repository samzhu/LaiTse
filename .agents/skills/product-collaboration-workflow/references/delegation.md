# 委派與協調

由單一人類窗口統整目標、優先序、跨功能相依和決策。人類可直接聯絡功能負責人；負責人須將相依和待決事項交回協調窗口。不要讓人類代為轉信或管理代理。

一位代理足以完成時就使用一位。只有工作確實獨立、需要不同能力或可獨立研究時才委派，避免只負責轉述的代理層級。每位負責人只提供完成任務所需的脈絡與資源。

開始前，在既有派工紀錄列明完整範圍包：精確資源／檔案、唯一 writer、讀寫模式、相依、不變條件、已授權決策、驗收、輸出與停止條件。派工表不是技術鎖。沉默、延誤或負責人無法聯絡都不代表釋出資源。只有明確交接已保存狀態、讀回結果、停止修改及剩餘工作後才可重派。

依獨立檔案／功能並行。同一檔案、共用元件、父層／主元件、相依實例、共用 manifest 或 lockfile 必須序列寫入。同一份需求文件只由一位 writer 寫入；其他人提供窄 patch。共用 UI 狀態由一位操作者控制；人類正在使用時先取得交接。API／工具操作與 UI 控制可能需要不同授權。

如有需要，可在 brief 記錄不綁供應商的能力與投入程度（例行／低、中等／中、複雜／高、例外／超高）。只映射到環境實際可用的選項。環境無法確認模型是否選定時，不要宣稱已選用。指定能力不可用時回報，不要靜默換用。

只有完成、實際阻擋、產品決策或資源交接才跨工作線回報。使用可用的完成事件等待；不要反覆輪詢，也不要宣稱尚未開始的工作正在執行。每次交付包含變更、證據、通過／未執行檢查、文件、待決事項與資源釋出狀態。
